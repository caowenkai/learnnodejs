01

JavaScript、V8 与 Node.js 的关系

JavaScript 是编程语言，V8 是执行 JavaScript 的引擎。Chrome 和 Node.js 都可以运行 JavaScript，但它们提供的额外能力不同。

JavaScript 语言本身：变量 · 函数 · 对象 · Promise · async/await
◉ Chrome 浏览器
JavaScript engine
V8 · 执行 JavaScript
Host APIs
DOM · window · localStorage
浏览器事件 · 页面渲染
⬢ Node.js
JavaScript engine
V8 · 执行 JavaScript
Host APIs
fs · http · process · path
异步 I/O · 事件循环

注意：Chrome 只是浏览器的一个例子，并非所有浏览器都使用 V8；Node.js 也可以运行在普通电脑上，不限定部署在服务器。

同一种语法，不同的运行环境

浏览器 JavaScript 
const x = 1 + 2;

document.querySelector('#app');
localStorage.setItem('token', '123');
Node.js JavaScript 
const x = 1 + 2;

console.log(process.cwd());
const fs = require('node:fs');
核心认知：Node.js 不是一种新语言，而是 JavaScript 的运行时环境。V8 负责执行 JS，而 Node 提供文件、网络、进程等系统能力，并借助底层机制管理异步 I/O。

为什么 JS 主线程只有一个，还能高并发？

真正需要区分的不是“Java 与 Node 谁更快”，而是 阻塞式线程模型 与 非阻塞 I/O 模型 如何处理等待。

⏱

发生了什么？JS 主线程迅速发起 A～E 的 I/O 后继续处理其他任务。5 段等待重叠，结果回来时再依次执行短暂的 JS 回调。

一个数字例子

假设 1000 个请求同时到达、每个请求等待 2 秒，忽略其他开销：

模型 / 约束理论完成时间
传统阻塞模型：100 个工作线程约 20 秒
异步 I/O：下游可同时承载 1000 个操作约 2 秒 + 调度开销

重要限定：现代 Java 也有 NIO、Netty 和虚拟线程，能够高效处理高并发 I/O。这里比较的是两种执行模型，不是证明 Node.js 一定比 Java 快。Node 的优势在于以比较自然的方式组织异步等待。

同样是 Node，阻塞和非阻塞差多少？

5 个请求同时发起，每个请求都需要“等待”2 秒。一个使用定时器模拟异步 I/O，另一个使用忙循环模拟 JS 主线程被 CPU 运算占住。

真实实验代码

demo.cjs · Node.js 服务端 
const http = require('node:http');

http.createServer((req, res) => {
  if (req.url === '/async') {
    // 异步定时器：模拟 I/O 等待
    setTimeout(() => res.end('ok'), 2000);
  } else if (req.url === '/block') {
    // 同步忙循环：占用 JS 主线程
    const start = Date.now();
    while (Date.now() - start < 2000) {}
    res.end('ok');
  } else {
    res.end('Demo ready');
  }
}).listen(3000);

在终端执行 node demo.cjs，然后打开 http://localhost:3000，进入浏览器开发者工具 Console：

浏览器控制台 · 并发测试 
async function test(path) {
  const start = performance.now();
  await Promise.all(
    Array.from({ length: 5 }, () => fetch(path))
  );
  console.log(path, ((performance.now() - start) / 1000).toFixed(2) + 's');
}

await test('/async'); // 通常约 2 秒
await test('/block'); // 通常约 10 秒
实验结论：非阻塞等待可以重叠；耗时同步代码却会阻塞 JS 主线程。定时器只是演示等待机制，不能据此推导真实数据库吞吐量，也不能用来判断不同编程语言的绝对性能。
04

哪些业务适合 Node.js？

判断的关键不是“请求数量多不多”，而是每个请求主要在等待外部结果，还是在持续消耗 CPU。

◌
客服系统 / WebSocket

大量长连接保持在线，主要等待消息和少量网络收发。

⌘
业务 API / 数据库 CRUD

等待数据库、Redis、网络返回结果，适合异步 I/O。

✳
AI API / Agent

调用远程大模型并等待生成结果，通常是网络 I/O 场景。

哪些场景需要格外注意？

复杂视频编码大规模图像处理耗时数学运算模型本地推理

长时间 CPU 密集型任务如果直接运行在 JS 主线程上，会拖慢其他请求。应考虑 Worker Threads、独立进程或专门计算服务。

KEY TAKEAWAY / 核心结论

Node.js 的优势不是 JavaScript 算得比其他语言更快，而是通过非阻塞 I/O 与事件循环，让大量等待中的请求不必一直占用 JS 主线程。

KNOWLEDGE NOTE / 知识提要

libuv 是什么？

libuv 是一个跨平台的 C 语言库，为 Node.js 提供事件循环、底层异步 I/O 支持以及线程池等基础能力。

V8执行 JavaScript 代码
libuv支持事件循环和异步 I/O

它怎么工作？

网络连接通常借助操作系统的非阻塞 I/O 事件通知（例如 Linux 的 epoll）；部分文件操作、特定 DNS 查询则会使用 libuv 的线程池。I/O 就绪或任务完成后，事件循环安排相应回调执行。

容易混淆的一点：异步不等于每个请求都启动一个线程；async/await 是 JavaScript 语言能力，也不是 libuv 提供的。

作为延伸概念了解即可，不需要学习 libuv 源码或 Event Loop phases。
